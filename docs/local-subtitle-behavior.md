# 本地 Qwen ASR + Hy-MT 字幕行为

优先级：延迟 > 减少分句闪烁 > 准确性 > 文本本身的稳定性。识别文字修正、译文替换不计入分句闪烁；反复拆合、搬行、内容消失后重现才是要减少的变化。

## 展示规则

- 本轮 ASR 已有内部句界，本轮就分成独立的原文/译文字幕单元。沿用小数、缩写、引号和省略号保护。
- 已显示的分行尽量保留。句号变逗号，只修订标点和文字，不默认将两条合回一条。分行不等于语法句子永久定稿。
- 原文、译文均可在稳定的字幕 ID 下继续修订。大幅重写无法对应旧分段时，允许重新分配，但不得丢字、重复文本或留下空条目。
- 末尾句号不创建空的下一条。连续无句号时，在已有逗号或空格附近分块；软长度目标为 CJK 64 字符、空格分词语言 180 字符。无空格的 CJK 可按长度兜底，英文单词不为凑长度截断。
- 原文先显示，不等待翻译。新译文到达前保留当前条已有译文，到达后原位替换；译文标点不决定字幕布局。

## 调度与状态

`LOCAL_INCREMENTAL_MIN_UPDATE_INTERVAL` 默认 0.3 秒，`LOCAL_INCREMENTAL_MAX_UPDATE_INTERVAL` 默认 4 秒。优先在自然语音停顿处更新；连续不停顿时才按 4 秒保底触发。普通语义扫描不能绕过这一节奏，已有候选句界仍允许快速确认。它们是触发条件，不是硬件无关的端到端延迟承诺。语义扫描结果同样进入展示路径，并在昂贵的音频切点探测前发布。

每个字幕单元持有独立的 Hy-MT 修订状态，各实例通过现有注册表共享同一个本地模型。上一版译文、前文和已识别的后文用于修订当前单元，后文明确只作参考。一个工作线程执行翻译；同一单元未开始的中间版本合并为最新版本，所有完成单元的最终结果都会排空。

在途译文若比当前显示版本新，可以先展示，即使 ASR 又增长了，以免持续讲话时译文一直被丢弃。它不能覆盖更晚已采用的版本，也不能在单元被删除、重新分割或改变翻译方向后写回旧结果。

`LocalSubtitlePipeline` 向现有 `update` 消息添加 `local_segments` 全字段 UPSERT 和 `local_removed_segment_ids`。每条有独立 ID、顺序、修订号和完成标记。前端保留稳定的渲染 token/节点，拒绝过期版本及已删除 ID 的迟到结果。普通在线 provider 的 token 协议保持兼容。

半透明原生悬浮窗同样消费这套逐条消息，按字幕 ID 更新原文及译文，不再依赖只供旧协议使用的 `final_tokens` / `non_final_tokens` 才显示本地字幕。

## 远程推理

设置中的“本地”模型提供方可进一步选择本机或远程推理。远程使用 Yakutan protocol v1 的统一 WebSocket 服务，同一个地址同时提供 Qwen3-ASR 与 Hy-MT2；本机保留音频采集、Silero CPU 停顿检测和本文的字幕分句/翻译调度。首次使用只可能补齐小型 Silero VAD，不加载本机 Qwen / Hy-MT 权重，也不要求本机的这两套模型已下载。

服务器连接测试是显式的 5 秒 WebSocket health 检查，普通设置状态读取不自动连接远端。地址、运行位置和推理超时随现有设置保存，并在后端重启后恢复。语义音频切点探测使用独立远程 ASR 连接，避免改写主识别连接的草稿；已完成的识别文本不回灌远程 ASR 上下文。

启动/隧道/停止脚本与部署限制见 [remote_inference_service/README.md](../remote_inference_service/README.md)。现有 Yakutan 服务可直接复用；复制的新服务端另支持可选后文参考字段，旧服务忽略它也能正常连接。

2026-09-06 验证：Python 全套 619 项、前端全套 678 项通过。通过已经存在的隧道接入 gpu4038 服务，对 12.106 秒连续三句音频实时回放，得到三条独立译文、无错误；首条原文 2.031 秒、首条译文 2.313 秒，整段排空 14.672 秒。测试阻止本地 Qwen/Hy-MT 引擎初始化，未执行远端启停或部署。这是单个样本的端到端结果，不是普遍延迟保证。

## 音频与完成

2026-10-26 起默认 `LOCAL_SEMANTIC_COMMIT_MODE=text`，定稿和裁音频分开。连续两次识别里同一个句末都在、句子的字词一致（标点、大小写改动不算，见 `LOCAL_SEMANTIC_BOUNDARY_LEXICAL_AGREEMENT`）、后面已有下一句的内容，就立刻把截至该句末的几句定稿，不跑探测，也不动音频。窗口只需 `LOCAL_SEMANTIC_TEXT_COMMIT_MIN_AUDIO_SECONDS`（默认 1.5 秒）。这些句子的音频继续留在窗口里，之后每次识别先把已定稿部分对齐剥掉，只显示剩下的部分。对齐只认连续成段的匹配，而且必须找到已定稿文本的结尾；对不上时先保持当前显示，连续三次对不上才放弃剥离，宁可重复一句也不让字幕卡住。

窗口里已定稿的语音累计约 6 秒（`LOCAL_SEMANTIC_TRIM_MIN_SECONDS`）后裁音频。切点放在最新一句已定稿句子估计开头之前约 0.5 秒，且至少在已定稿结尾前 2 秒（`LOCAL_SEMANTIC_TRIM_MARGIN_SECONDS`），再挪到附近 VAD 最不像语音的位置，只跑一次探测。这样最新一句连同一点上文都还在窗口里，切口处的词就算被重新识别成别的字（中文同音字很常见），后面的识别仍能靠这一句对齐。探测出的文字必须完整落在已定稿文本里，且之后还剩一些已定稿文本，才裁掉这段音频；否则再往前 1.5 秒试一次，仍不行就等下一次定稿。VAD 静音结束或 30 秒上限时，整窗 final 同样剥掉已定稿部分；对不上或剥完为空时，用屏幕上最后一次显示的待确认文字收尾。

Qwen 解码默认改为贪心（`LOCAL_QWEN_ASR_TEMPERATURE=0`），推测解码校验时还倾向沿用上一次中间结果：草稿词的 logit 与模型首选相差不超过 `LOCAL_QWEN_ASR_DRAFT_BIAS`（默认 2.0，即模型认为它的可能性至少是首选的 13.5%）就保留，草稿最后 6 个 token（`LOCAL_QWEN_ASR_DRAFT_BIAS_TAIL_TOKENS`）不受偏向，留给新音频修正。原来每次都以温度 0.4 随机采样，相邻两次识别会把近似并列的词和逗号/句号来回翻，待确认的旧句子也跟着反复改写。复读熔断后的重试仍用随机温度。远程推理服务端有自己的解码设置，不受这两项影响。

以下几段描述 `LOCAL_SEMANTIC_COMMIT_MODE=audio`，即此前的默认行为。`LOCAL_SEMANTIC_BOUNDARY_ENABLED` 默认开启，决定是否尝试保守的语义音频裁剪；关闭或定位失败不阻止文字分行。音频窗口达到 `LOCAL_SEMANTIC_BOUNDARY_MIN_AUDIO_SECONDS`（默认 8 秒）后，寻找连续两次识别保持一致、且有后文的最后一个安全句末，再用独立 ASR 探测定位音频切点。一次可以移走多句已经完成的音频，避免每次只移走最前一句而赶不上持续讲话。8 秒是启动裁剪判断的门槛，不是每次请求的硬上限，也不让原文或翻译等到 8 秒才更新。

切点前保留 0.8 秒重叠重放，减少切掉下句开头的风险。始终没有可靠句界或定位失败时，仍由 `LOCAL_VAD_MAX_SPEECH_DURATION`（默认 30 秒，实际受音频块粒度影响）强制结束窗口。此兜底可能切在句中；不能为了等句号而无限累积音频。

成功裁剪时，回调先发布完整 partial，再以 `semantic_suffix_text` 交接已知尾部。前缀完成，尾部字幕 ID、文字和译文保留；随后尾部识别仅作修正。普通静音或窗口结束时，完成当前所有字幕单元。日志、IPC 和 OSC 的最终提交按语音顺序进行。

2026-09-06 连续音频裁剪验证：将同一段三句中文音频重复三遍，按实时速度输入 36.317 秒，使用正常 Silero VAD 和现有远程 Qwen 服务。旧逻辑裁剪 5 次，主识别请求最长 17.192 秒；调整后裁剪 3 次，最长 12.485 秒，每次裁剪后的首个尾部请求分别为 4.954、4.905、4.837 秒。九句话完整保留，无定位失败或识别异常。该样本说明窗口积累有所改善，不代表所有语速、语言或设备都能维持相同上限。

重叠重放出现两三个汉字或一个完整单词时，仅在后续文字匹配裁切时已知尾部的 6–8 个有效字符后，才允许短重叠去重。缺少这项证据时保留原有保守阈值；不能仅凭内容重复删除整条识别结果。

停止时先排空 ASR，再排空字幕翻译，最后释放模型。后续语音段获得新 ID，合法重复讲话不按旧句内容去重。已经完成的识别原文不回灌下一段 ASR 提示词。
