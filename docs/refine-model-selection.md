# 实时字幕修正：本次选定方案

后续千问专项调优完成于 2026-10-01，默认仍保留此 DeepSeek 配方；新一轮同样本结果及
千问候选提示词见 [qwen-flash-tuning.md](qwen-flash-tuning.md)。不同轮次评分不要直接相减。
同日补测 OpenRouter Gemma 4 31B，仍保留当前默认，配方与质量/长尾/费用对照见
[gemma4-refine-evaluation.md](gemma4-refine-evaluation.md)。

2026-09-30 选择 **DeepSeek `deepseek-flash` + 通用语义示例提示词**，非思考模式，
temperature 0.2，max_tokens 1024，三句原文上下文。提示词已写入 `llm_refine.py`，
本机 `.env` 已激活对应 DeepSeek 配置。提示词快照 SHA256：
`5fb9d9017fc7d7b2242977ab6b4695a99fd9da93cf72749c721134c3e6176bc1`。

提示词检查对象、动作、主客体、否定、条件、名字、数字、漏译与多译；允许正确的口语、
同义词、重复和半句话。只替换错误片段、保留其余草稿。六个通用示例展示保持正确译文、
主客体反转、必要条件和日语否定，不包含历史 benchmark 原句。

选择目标是修好意思、保持可读、减少字幕跳动。它没有把“少改”当成胜利：千问原方案
修改最少，却漏掉了多数实质错误。最终方案的通顺均分略低于旧 DeepSeek，但仍高于
原草稿；这是减少自动润色的实际取舍。

## 同轮匿名评测

800 条历史英译中/日译中各 400，独立 Luna 同轮盲评，语义/通顺度为 0–4 分。
“实质错误”定义为草稿语义 ≤2；修好定义为最终 ≥3。本轮判定 90 条草稿有实质错误。

|方案|语义|通顺|修好实质错误|新增实质错误|纯风格改写|修改句数|
|---|---:|---:|---:|---:|---:|---:|
|原始草稿|3.628|3.780|0|0|0|0|
|旧 DeepSeek + 旧提示词|3.739|3.895|54/90|12|150|267/800|
|原 Qwen + 用户新提示词|3.676|3.799|17/90|2|35|74/800|
|选定 DeepSeek + 示例提示词及输出校验|3.768|3.855|59/90|9|78|189/800|

相对旧 DeepSeek，纯润色减少 48%，修改率从 33.4% 降到 23.6%，修好数增加 5，
新增实质错误减少 3。整体语义配对差 +0.02875，会话 bootstrap 95% 区间
[+0.00266, +0.05451]；不能把这个小分差解释成独立于裁判偏差的质量保证。
剔除裁判不确定或评分/文字矛盾后，702 对的均差为 +0.01567。

英语语义均分 3.825 对旧方案 3.785，新增实质错误 1 对 5；日语整体差异较小，
剔除裁判不可靠样本后两方案语义分相同。日语仍可能误解多义词和含混口语：本次
新方案日语新增实质错误 8，旧方案 7，不能宣称每个方向都减少了误修。

## 留出会话与语义验收

按整个日志会话划分开发集 202 条、留出集 598 条，没有会话交叉。模型/提示词选择
依据开发集和合成题；最终提示词冻结后生成留出集结果。最初两套基线的全量评分此前
已看过，所以这不是完全从未见过的数据。早先 short_patch 候选曾生成全量输出，
但未查看其留出质量或用于提示词选择；合成验收失败后被放弃。

|598 条留出样本|修好实质错误|新增实质错误|纯风格改写|修改句数|
|---|---:|---:|---:|---:|
|旧 DeepSeek|39|8|122|208|
|原 Qwen|12|2|26|58|

留出集语义配对差 +0.03679，95% 区间 [+0.00566, +0.06734]；剔除不可靠裁判结果后

结果也保留在 `final-recipe-800/pre-gate/`，便于区分提示词收益与解析器收益。

20 道新合成题在提示词冻结后验收：10 句正确草稿全部原样保留，10 句明确错误全部

检查，允许不同措辞。这是本次人工式逐条检查，不是语言模型自身给出的通过率。

## 输出校验

800 条中发现 3 次模型夹带解释。新增校验遇到明确的说明、原句加箭头、输入中没有的
Source/Draft/Issues/Corrected 字段或单独 NO_CHANGE 标记时保留草稿，不把说明上屏。
输入本来就含这些字段或箭头时保留字面内容。所有 2400 个原始响应用同一解析器重新
处理，只有选定方案的 3 条变化，并仅对这 3 条重新盲评；其他结果不改。原始响应和
校验前统计保留。这个校验不能发现任意形式的解释，更不能判断所有语义错误。

## 时延和费用

另外用 60 条开发样本交错发新请求，三方案同批、并发 4；未使用早先复用结果的时延。

|方案|HTTP p50|HTTP p95|
|---|---:|---:|
|旧 DeepSeek|565 ms|976 ms|
|原 Qwen|427 ms|634 ms|
|选定 DeepSeek|516 ms|859 ms|

这是成功 HTTP 请求时延，不含 ASR、队列和 UI，也不保证线上长尾。

按这轮 800 条实际成功响应的输入、输出、缓存 token，以及 2026-09-30 官方单价估计，
每 1000 句选定 DeepSeek 约 **US$0.0345–0.0689**（非高峰/高峰），旧方案约
US$0.0275–0.0551。单价为缓存输入 $0.003/$0.006、未缓存输入 $0.15/$0.30、
输出 $0.60/$1.20 每百万 token；实际账单还受缓存与重试影响。
依据：[DeepSeek 官方定价](https://api-docs.deepseek.com/quick_start/pricing/)。

原 Qwen 在北京地域非思考、输入 ≤32K 档位约 **¥0.0417/1000 句**，按输入 ¥0.2、
输出 ¥0.8 每百万 token 估计。本轮未记录缓存命中。保留各自计费币种，不假设汇率。
依据：[Qwen3.7 Flash 官方定价](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)。
更便宜的原 Qwen 本次漏修明显更多，故当前默认选择 DeepSeek。

## 迭代和复跑记录

开发阶段比较英文/中文约束、短提示词、通用示例、歧义保护和温度 0/0.1/0.2。
过强“不要改”导致漏修；短提示词历史分数不错，但漏修明确条件/人物关系。
通用示例修复了这些问题；额外歧义约束没有稳定收益。Qwen 放宽约束后改动和误修
增加。DeepSeek 低思考模式在 2048 输出预算下 13/202 无最终答案，故没有设为默认；
Qwen 思考小样本更慢，也未稳定修好主客体。LongCat 只做合成小样本筛查，未胜出；
MiMo 配置返回 HTTP 402，未计为质量失败，也未充值。

工具、协议和人工复核流程见 [refine-benchmark.md](refine-benchmark.md)。固定数据
与逐条原文/草稿/输出保存在 Git 忽略的 `scratch/refine-tuning/`：

- `frozen-decision-final.json`、`split.json`：选择理由和分组 ID。
